# WhatsApp AI Platform — каркас

Спринт 0. Не продукт, а фундамент: монорепо, база, очередь, приём вебхука и слой изоляции арендаторов.

## Запуск

```bash
cp .env.example .env
openssl rand -base64 32   # → AUTH_SECRET
openssl rand -base64 32   # → ENCRYPTION_KEY

docker compose up -d
pnpm install
pnpm db:generate
pnpm db:migrate --name init
pnpm db:seed

pnpm dev
```

Открыть `http://localhost:3000/api/health` — должно вернуться `{"status":"ok","db":"up"}`.

## Проверить, что цепочка работает

Воркер должен быть запущен (`pnpm dev` поднимает и web, и worker).

```bash
curl -X POST http://localhost:3000/api/webhooks/whatsapp \
  -H "Content-Type: application/json" \
  -d '{
    "entry": [{
      "changes": [{
        "value": {
          "metadata": { "phone_number_id": "TEST_NUMBER_ID" },
          "contacts": [{ "profile": { "name": "Тест" } }],
          "messages": [{
            "id": "wamid.test1",
            "from": "77011234567",
            "type": "text",
            "text": { "body": "Привет" },
            "timestamp": "1700000000"
          }]
        }
      }]
    }]
  }'
```

Ответ приходит мгновенно, дальше событие разбирает воркер. Пока в базе нет номера с
`phoneNumberId = TEST_NUMBER_ID`, событие честно помечается `IGNORED` — привязка номеров
появится в спринте 2.

## Что где лежит

```
apps/web              Next.js — интерфейс и HTTP-слой (вебхуки, API)
apps/worker           фоновый процесс: разбор событий, позже AI и индексация
packages/db           Prisma-схема, клиент, tenant-расширение, тесты изоляции
packages/core         бизнес-логика без фреймворка: права, окно 24ч, шифрование
packages/whatsapp     интерфейс провайдера + мок (Cloud API — спринт 6)
```

Бизнес-логика намеренно не живёт внутри Next.js. Если через год backend поедет
в отдельный сервис, переезжает слой роутов, а не продукт.

## Правила, которые нельзя нарушать

**1. Данные арендатора — только через `forCompany()`.**

```ts
const db = forCompany(prisma, session.companyId);
const customers = await db.customer.findMany();   // companyId подставится сам
```

Голый `prisma` допустим только там, где компании ещё нет: регистрация, приём вебхука,
супер-админка. Каждый такой вызов — осознанное решение, а не привычка.

`findUnique`, `update`, `delete` и `upsert` для таблиц арендатора запрещены расширением
и бросают `TenantScopeError`: в них Prisma принимает только уникальный `where`, куда
`companyId` не подставить. Вместо них — `findFirst`, `updateMany`, `deleteMany`.

**2. Новая таблица с `companyId` — сразу в `TENANT_MODELS`.**
Тест `tenant-isolation.test.ts` сверяется со схемой и падает, если список отстал.

**3. Вебхук не делает ничего долгого.** Проверил подпись → записал событие → положил
в очередь → ответил 200. Синхронная обработка приводит к ретраям Meta, дублям ответов
и просадке качества номера.

**4. Секреты не хранятся в открытом виде.** Токены Meta проходят через `encryptSecret()`,
в интерфейс отдаются только через `maskSecret()`.

**5. Вне 24-часового окна — только шаблоны.** Любая отправка свободного текста идёт
через `assertCanSendFreeText()`.

## Спринт 2 (частично): живой инбокс

Страница `/conversations` работает на настоящей базе — список диалогов, переписка,
отправка, «Забрать диалог» / «Вернуть ассистенту».

```bash
docker compose up -d
pnpm install && pnpm db:generate && pnpm db:migrate --name init && pnpm db:seed
pnpm dev            # → http://localhost:3000/conversations
```

Проверить приём входящего: команда с curl выше в этом README. Номер `TEST_NUMBER_ID`
создаётся сидом, поэтому событие теперь не игнорируется — сообщение появится
в интерфейсе в течение восьми секунд.

Что здесь честно временное:

- **Компании нет в сессии.** `requireCompany()` берёт `DEV_COMPANY_ID` или первую
  компанию в базе. Авторизация появится в спринте 1 — меняется только тело этой функции.
- **Обновление опросом раз в 8 секунд.** SSE — спринт 3.
- **Отправка идёт в мок-провайдер**, то есть в консоль. Cloud API — спринт 6.
- **Подсказок ассистента на экране нет**, потому что ассистента ещё нет — спринт 4.

Окно 24 часов уже настоящее: если последнее сообщение клиента старше суток, поле
ввода блокируется, а `assertCanSendFreeText()` не пропустит отправку даже в обход UI.

## Спринты 4–5: ассистент и база знаний

```bash
docker compose up -d
pnpm install && pnpm db:generate && pnpm db:migrate --name ai_knowledge

# ОБЯЗАТЕЛЬНО: колонка эмбеддингов и индекс — Prisma их не умеет
psql "$DATABASE_URL" -f packages/db/sql/vector.sql

pnpm db:seed && pnpm dev
```

В `.env` нужны два ключа: `ANTHROPIC_API_KEY` (генерация) и `OPENAI_API_KEY`
(эмбеддинги, модель `text-embedding-3-small`). Без второго база знаний
не проиндексируется.

Порядок проверки:

1. `/assistant` — заполнить роль, задачи, запреты, порог. Внизу видно точный
   текст, который уходит модели.
2. `/knowledge` — загрузить файл или вписать текст руками. Индексация идёт
   в воркере, статус меняется `В очереди → Индексируется → Готов`.
3. Там же справа **Проверка поиска**: видно найденные фрагменты, их score
   и итоговый ответ.
4. `/playground` — диалог с памятью, ответы с уверенностью и источниками.
   В WhatsApp ничего не уходит.
5. Отправить событие на вебхук (curl выше) — ассистент ответит сам,
   если включён и диалог в режиме AI.

### Как считается уверенность

Самооценка модели ненадёжна — модель охотно ставит себе 95%, опираясь
на общие знания. Поэтому итог ограничен качеством найденных фрагментов:

```
confidence = min(оценка модели, близость лучшего фрагмента × 100)
```

Если ни один фрагмент не набрал 0,35 близости, запрос к модели вообще
не отправляется: ответа в базе нет, звать надо человека. Так же
обрабатывается ответ, не разобравшийся как JSON, — это сбой, а не повод
отправить клиенту сырой текст.

Запрет на выдумывание дописывается к инструкции всегда, включая ручной
режим. Пользователь может изменить тон и задачи, но не может разрешить
ассистенту сочинять наличие, цены и сроки.

### Что здесь честно не сделано

- **Скан без текстового слоя не читается** — нужен OCR, его нет.
- **Голосовые не транскрибируются** — поле под медиа есть, обработки нет.
- **Файл не сохраняется в хранилище**: текст извлекается при загрузке, сам
  файл не остаётся. Для переиндексации документ придётся загрузить заново.
- **Ivfflat-индекс** строится по текущим данным. После первой большой
  загрузки пересоздай его, иначе поиск идёт полным перебором.
